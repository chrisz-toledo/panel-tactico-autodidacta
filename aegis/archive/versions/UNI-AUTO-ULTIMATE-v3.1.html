🧭 1. Filosofía: El Efecto del Agua Ascendente

▼

🌊 El Rising Water Effect

La IA ha subido el piso: más personas pueden producir código. Pero también ha subido el techo más rápido: menos personas pueden producir sistemas robustos.

✅ La IA acelera MECÁNICAS, no JUICIO

Escribe funciones rápido. Genera tests. Pero NO decide arquitectura. NO evalúa riesgos. Eso es tu trabajo.

✅ Trata el output de IA como "código junior sin revisar"

Nunca deployes código IA sin revisarlo. La IA no tiene responsabilidad legal. Tú sí.

✅ Invierte en FUNDAMENTOS, no en prompts

Saber escribir un buen prompt es útil. Saber por qué el código funciona es invaluable.

⚠️ La Trampa del "Vibe Coding"

"Vibe coding" = prompt a producción sin revisión. Caso Moltbook (2025): app 100% vibe-coded expuso millones de registros. Caso Enrichlead: la IA puso toda la lógica de seguridad en el cliente.

⚠️ 2. Los 6 Riesgos de Seguridad del Código IA

▼
🔴 Riesgo 1: Credenciales Hardcodeadas

La IA genera código con API keys escritas directamente. Fix: Variables de entorno. .gitignore. GitGuardian.

🔴 Riesgo 2: Remote Code Execution (RCE)

Claude generó código usando pickle de Python. Fix: Pregunta "¿Cuáles son los riesgos de seguridad?"

🔴 Riesgo 3: Autenticación Rota

Sin rate limiting, sin verificación de email, permisos excesivos. Fix: Revisión manual obligatoria.

🔴 Riesgo 4: Inyecciones (SQL, XSS, Command)

La IA concatena input de usuario en strings SQL. Fix: Parametrización SIEMPRE.

🔴 Riesgo 5: Dependencias Fantasma

La IA alucina nombres de paquetes. Algunos son maliciosos. Fix: npm audit / pip-audit.

🔴 Riesgo 6: Deuda Técnica Masiva

El codebase crece más rápido de lo que nadie puede entender. Fix: Tests, documentación, ownership.

🛡️ 3. Framework de Seguridad para Código IA

▼
1. Aislamiento a Nivel de Infraestructura

NGINX o Cloudflare Zero Trust como gate de entrada. Seguridad incluso si el código está roto.

2. Multi-Stage Security Prompting

Paso 1: Construye la feature. Paso 2: Actúa como Security Engineer y revisa tu propio código. Paso 3: Reescribe endurecido.

3. Guardrails (.cursorrules / .mdc)

Archivos de reglas que establecen líneas rojas para la IA. PROHIBIDO: hardcoded secrets. REQUERIDO: parameterized queries.

4. TDD con Agentes

"Escribe tests → Deben fallar → Commit → Escribe implementación → NO modifiques tests → Sigue hasta que pasen."

5. Humano en el Loop

Auth, pagos, permisos, datos sensibles: SIEMPRE revisión humana. Sin excepciones.

🔄 Los 5 Pilares del Pensamiento Sistémico

▼
1. Abstracción-Jerarquía
Usuario → API → Negocio → Persistencia → Infra. Cada capa es un sistema con contratos.
2. Estado-Transición
Transiciones atómicas, trazables, seguras. Dibuja diagramas antes de programar.
3. Fallo-Primero
Asume que todo fallará. Diseña para recuperación. Separa junior de senior.
4. Seguridad por Diseño
Propiedad emergente. Threat modeling (STRIDE) en cada proyecto.
5. Composición-Reutilización
Elige componentes correctos. Define sus interacciones.

✍️ Ritual Diario de Arquitecto

Antes de VS Code: 1) Dibuja en papel. 2) Escribe contratos. 3) 3 ataques + 3 defensas. 4) Luego programa.
